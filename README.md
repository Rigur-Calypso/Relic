# RELIC — The Self-Healing Web Memory

> **A healthy scraper is not the same as preserved knowledge.**
> Built for the Bright Data *Scrape-Verse* Hackathon.

RELIC monitors scientific & academic facility websites (national labs, university
core facilities) and answers a question no ordinary scraper can:
**"What knowledge did this page silently lose?"**

For every monitored lab it (1) scrapes the **live** page through Bright Data,
(2) pulls the **historical** version from the Wayback Machine, and (3) runs a
**Gemini semantic diff** between them — producing a `vitalityScore` and an explicit
list of equipment that was *removed, added, or modified* over time.

---

## The insight

You can fix a scraper so it happily returns `200 OK` and clean rows, and still be
silently losing the fact that a lab **decommissioned its Atomic Force Microscope.**
Scraper health is a plumbing metric. Knowledge continuity is the real signal.
**RELIC surfaces both.**

### The "Dual-Heal"

- **Heal #1 — the scraper heals itself.** When a page's DOM changes and the brittle
  CSS-selector extractor returns zero rows, RELIC re-extracts the *same
  Bright-Data-fetched content* with Gemini (layout-agnostic) and restores structured
  output. The scraper is green again. *This is the heal everyone celebrates.*
- **Heal #2 — the knowledge does NOT heal.** RELIC keeps going and diffs the healed
  current data against the Wayback history, reporting that even though the *scraper*
  recovered, a real capability is **gone.** *This is RELIC's reason to exist.*

## Where Bright Data does the heavy lifting

1. **Live extraction.** Every scrape runs through the Bright Data Web Unlocker
   (`bdata scrape <url> -f markdown|html`), which returns clean, bot-bypassed content
   even from ancient, JS-heavy, or lightly-defended institutional sites.
2. **Layout-agnostic re-extraction (the heal).** Because Bright Data returns clean
   content regardless of how the DOM mutated, Gemini can re-extract structured
   equipment rows from it — that resilient content is what makes the heal possible.
3. **Resilient history.** The Wayback Availability API rate-limits hard (HTTP 429).
   RELIC routes the `web.archive.org/web/<ts>/<url>` snapshot fetch **through Bright
   Data's proxies**, which bypass the IP-level block — so even the historical layer is
   Bright-Data-resilient.

## Architecture

```
 targets.json ─┬─ (A) LIVE  ── src/scraper ──── bdata scrape ─► cheerio (L1) / Gemini (L2)
               │                                                    └─► data/current/<id>.json
               └─ (B) HISTORY ─ src/analyzer/wayback.js ─ bdata→Wayback ─ Gemini
                                                                    └─► data/historical/<id>.json
                                    data/current + data/historical
                                                │
                                    src/analyzer/diff.js  (Gemini semantic diff)
                                                └─► data/analysis/<id>.json
                                                │
                                    src/api/server.js  (Express :3001)
                                                │  (Vite proxy /api → 3001)
                                    src/frontend  (React + Tailwind, :5173)
```

- **All state is flat JSON** in `data/` (no database, no native modules — runs clean
  on Apple Silicon).
- **Canonical record:** every source normalizes to `{ name, specifications, location, status }`.

## Tech stack

| Layer | Choice |
|-------|--------|
| Runtime | Node.js ≥ 20, ESM |
| Scraping | **Bright Data CLI** (`@brightdata/cli`) — Web Unlocker |
| AI | **Gemini** via `@google/genai` (`gemini-3.6-flash`), strict JSON schema |
| History | Wayback Machine (fetched through Bright Data) |
| Backend | Express (:3001), flat-JSON store |
| Frontend | React + Vite + TailwindCSS (:5173) |
| HTML parse | cheerio (pure-JS Layer-1 selector) |

## Quickstart

```bash
# 0. Prereqs
node -v                      # >= 20
npm i -g @brightdata/cli
bdata login                  # one-time browser OAuth

# 1. Install
npm install

# 2. Configure .env  (see .env.example)
#    GEMINI_API_KEYS=key1,key2,...   ← comma-separated free-tier pool (auto-rotated)
#    GEMINI_MODEL=gemini-3.6-flash

# 3. Run the pipeline for one target (or omit the id for all)
npm run scrape  -- saif-iitb
npm run wayback -- saif-iitb
npm run analyze -- saif-iitb

# 4. Launch (two terminals)
npm run api                        # backend  :3001
cd src/frontend && npm run dev     # dashboard :5173
```

Open the dashboard, click any lab, and read its semantic diff.

## Engineering highlights

- **Multi-key Gemini rotation** (`src/gemini.js`). The free tier caps at 20
  requests/day/key. RELIC accepts a comma-separated `GEMINI_API_KEYS` pool and
  auto-rotates to the next key on a quota error, persisting which keys are spent
  (`data/.gemini-state.json`) across the separate `scrape`/`wayback`/`analyze`
  processes, and resetting at Pacific midnight. Invalid keys are skipped; transient
  5xx are retried on the same key.
- **Graceful degradation.** Missing Wayback snapshots, empty pages, and DNS failures
  never crash a run — the target simply reports "no history" or "0 equipment".
- **Honest "self-healing".** RELIC's heal is a real, demonstrable *product* feature
  (brittle selector → AI re-extraction), not a fictional Bright Data command.

## The interactive demo (decoy)

`decoy-site/index.html` is a lab page we control (SEM, XRD, **AFM**). Deploy it to
GitHub Pages, then on stage:

1. Break it live — rename `id="equipment-table"` **and** delete the AFM `<tr>`.
2. `npm run scrape -- decoy`  → dashboard flips to **FAILED / 0 equipment**.
3. `npm run heal  -- decoy`   → **HEALTHY** again (Gemini re-extract).
4. `npm run analyze -- decoy` → **"Knowledge Lost: Atomic Force Microscope removed."**

*Scraper healthy, knowledge lost.* (Deployment steps in [SETUP.md](SETUP.md).)
